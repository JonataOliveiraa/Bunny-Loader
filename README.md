# Bunny Loader

A mod loader for **Terraria Mobile**. It is an Android app that boots the game
inside its own process, hooks methods of the native code generated by IL2CPP
and runs mods written in **JavaScript**, in the tModLoader style
(`ModItem`, `ModNPC`, `ModProjectile`, `SetDefaults`, `AI`...).

![The Bunny Loader home screen](docs/imagens/launcher-inicio.jpg)

- JavaScript mods (the [QuickJS](https://github.com/quickjs-ng/quickjs) engine,
  no JIT), with direct access to the game's classes and `hook()` on any method.
- New content as in tModLoader: items, weapons, projectiles, pets, minions,
  enemies, town NPCs with shops, bosses with music, tiles, walls, buffs,
  recipes.
- Damage classes (`DamageClass`): "melee", "magic" or a brand-new class from
  your mod (a rogue, a bard), with per-class damage, crit, attack speed, armor
  penetration and knockback bonuses, inheritance between classes and the class
  name in the tooltip.
- Clean saves: mod content is stored next to the game's save, by name, and the
  world still opens without the mod.
- In-game Mod Menu: the items and NPCs of each mod, plus superpowers.
- Per-mod options in the pause menu, under **Mod Configuration**: toggles,
  sliders and single-choice options on the game's own Settings screen
  (tModLoader's `ModConfig`).
- Online catalog: the launcher's **Explore** tab lists published mods and
  downloads and updates them with one tap, with no account and no token in the
  app.

> This repository does **not** include Terraria's binaries or assets
> (`libil2cpp.so`, `libunity.so`, the game data), Unity's Java classes or the
> Andy font: they stay out of Git and are integrated locally, and the game only
> opens for people who have the official Terraria from Google Play installed.
> The dumps in `refs/` are generated locally and never published. Some UI
> textures (backgrounds, menu icons, example mod covers) are crops of Terraria's
> art, generated by `tools/ui-sprites.py` and `tools/mod-art.py`.

## A mod in 10 lines

```js
// content/main.js: every weapon hits twice as hard
Terraria.Item['void SetDefaults(int Type, ItemVariant variant)'].hook((original, self, type, variant) => {
    original(self, type, variant);
    if (self.damage > 0) self.damage *= 2;
});

bl.log('Double Damage: active');
```

The complete examples are in [`samples/`](samples), from the smallest
([`DobroDeDano`](samples/DobroDeDano)) to [`ExampleMod`](samples/ExampleMod),
the port of tModLoader's.

## Stack

| Layer | Technology |
|---|---|
| App and launcher | Kotlin + Jetpack Compose |
| Native core | C++20 (NDK + CMake) → `libbunny.so` |
| Hooks | [ShadowHook](https://github.com/bytedance/android-inline-hook) (inline, ARM64), with our own chain |
| IL2CPP | the embedding API (`il2cpp_*`), via `dlsym`; everything resolved by name |
| Mod engine | QuickJS (quickjs-ng) |
| Game dump | Il2CppDumper |

## Layout

```
app/src/main/
  kotlin/dev/bunnyloader/   Android app: the launcher and the GameActivity that boots Unity
  cpp/                      Native core (libbunny.so); map in docs/nucleo/README.md
  res/                      Android resources
samples/                    Example mods, from the simplest to ExampleMod
docs/                       Documentation (guides, reference, core, history)
tools/                      PC tools: fast build, dump, tests, benchmark
refs/                       Local game dump (NOT versioned)
```

## Build

Open the folder in Android Studio and let **Gradle Sync** run: it downloads
Gradle and offers to install any missing SDK platform.

1. SDK Manager → **SDK Tools** tab → install **NDK (Side by side)** and
   **CMake**.
2. Clone QuickJS into `app/src/main/cpp/third_party/quickjs/` (see the
   [README there](app/src/main/cpp/third_party/README.md)). Without it the
   build passes and the mod engine runs in stub mode.
3. The game runtime (the `.so` files in `app/src/main/jniLibs/arm64-v8a/` and
   the data in `terraria1456_assets/`) is not in the repository; see the
   [folder's README](app/src/main/jniLibs/arm64-v8a/README.md). Without it the
   app builds and installs, and `GameActivity` reports that the runtime is
   missing.
4. Unity's classes (`app/libs/unity-classes.jar`) and the Andy font
   (`app/src/main/res/font/bunny.ttf`) also stay out of Git, since they belong
   to third parties. Without the jar the game does not boot ([`app/libs/README.md`](app/libs/README.md));
   without the font the app uses Comic Neue ([`app/src/fontFallback`](app/src/fontFallback/README.md)).

Shortcuts:

| | |
|---|---|
| `-Pbl.nativeBuild=false` | Launcher only, no NDK or CMake. |
| `-Pbl.uiOnly=true` | Without the game's assets and `.so` files: the UI cycle drops to ~6 s ([`tools/ui.sh`](tools/ui.sh)). |

### Release APK

`assembleRelease` signs with the key from `keystore.properties` at the root
(copy [`keystore.properties.example`](keystore.properties.example), which also
has the `keytool` command to create the key). The variables
`BL_RELEASE_STORE_FILE`, `BL_RELEASE_STORE_PASSWORD`, `BL_RELEASE_KEY_ALIAS` and
`BL_RELEASE_KEY_PASSWORD` work too. The key and the file stay out of Git.
Without them, the release APK comes out unsigned.

Keep the key safe: Android only updates the app in place with the same
signature. Anyone who installed a debug APK has to uninstall it before moving
to the release one.

### Game dump

```bash
tools/dump.sh
```

Generates `refs/` (the `dump.cs` with every class, field and method of the
game) from the installed Terraria. See [`refs/README.md`](refs/README.md).

### Tests

The tests are mods in [`tools/tests/`](tools/tests), run on the emulator by
[`tools/bench/run.sh`](tools/bench/run.sh). See [`tools/README.md`](tools/README.md).
Development happens on MuMu Player (which runs the game's ARM code through
translation, and where hooks work) and is checked on a real ARM device.
