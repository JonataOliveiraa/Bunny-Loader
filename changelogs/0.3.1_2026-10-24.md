# Bunny Loader 0.3.1 — 2026-10-24

A small version after `0.3.0`, from Oct 22 to Oct 24, 2026: the black screen when opening the game with a large mod, a picture viewer on the mod page and translated summaries.

## For players

- **Picture viewer:** on a mod's page, tap the icon, the banner or any screenshot to open it full screen. Swipe to the next one, pinch or double-tap to zoom, use the strip of thumbnails at the bottom to jump straight to one, and tap outside the image (or press back) to close. Pixel art stays sharp when enlarged.
- **Summaries in your language:** a mod can ship its one-line summary translated, and the list card, the featured card, the search and the mod page use the one for your language. The Example Mod comes with English and Chinese.
- The catalog's web page shows the translated summary as well.

## Fixes

- **Black screen when opening the game with mods.** Reported with Thorium; it came and went depending on how busy the phone was. Three causes, all fixed:
  - The loader's start-up thread registered itself with the game's runtime and ended without unregistering. The garbage collector then waited for it forever, and the game thread with it.
  - Mods loaded while the game was still loading its own content. The game's language loading walked the text table while mod items added keys to it ("Collection was modified"), and the game's loading never finished. Mods now wait for the game to finish loading before they load.
  - While mods were loading, every hooked method called from a game thread waited up to 3 seconds for the script engine, once per call: hundreds of `NPC.SetDefaults` calls added up to minutes. Those calls now run the game's method right away, with a single warning in the log.
- The game's language hook no longer waits for the script engine either. If the game reloaded its language while mods were loading, the mod texts are put back at the end of the load.
- Animated mod tiles could read past the game's tile tables in the first frame after loading.

## Performance

- Loading a large mod with `AppliesToEntity` globals took tens of seconds: the filtered list was stored on every item, NPC and projectile the game creates at start-up (thousands of them). It is now a table per type, and nothing is written on the entity.
- A hook that already gave up on a long hold of the script engine (a heavy world generation pass, for example) no longer waits 3 seconds again on every call for the same hold.

## For modders

- **`localizedSummaries`** in `manifest.json`: the summary keyed by game culture (`pt-BR`, `en-US`, `ru-RU`, `es-ES`, `zh-Hans`), with `summary` as the fallback. See guide 13 and the README.
- **`bl.yield()`**: releases the script engine for an instant and takes it back. Call it between steps of long JS work on a game thread (a world generation pass of tens of seconds), every few tens of milliseconds, so the game threads returning from a hook's `original()` do not freeze the screen.
- **`AppliesToEntity` runs once per type**, with the first entity of that type, and the result is reused for every entity of that type. Globals that need per-entity state keep using `InstancePerEntity`, which runs the filter per entity as before.

## Installing and updating

- Same signature as 0.3.0 and 0.2.0: installs over them, no uninstall needed.
