| `ref List<int>[] GrantImmunityWith` | static property | differs | An NPC will automatically become immune (`buffImmune`) to the indexed buff type if it is already immune to any buff in the corresponding List. For NPCs with `ImmuneToWhipTags` or `ImmuneToRegularBuffs` set to true, the reverse of that logic is used to automatically set the NPC as vulnerable: The NPC will automatically become vulnerable to the indexed buff type if it is specifically vulnerable to all of the buffs in the corresponding List. Modders can use this set to create buffs that act as variants of existing buffs, and should inherit the immunity value of those existing buffs. ## BuilderToggle

The `Active` method determines if the BuilderToggle should be shown to the user and is usually reliant on player-specific values. ## SetFactory

`struct Terraria.ID.SetFactory`

SetFactory is responsible for creating "custom ID sets" for content. "Custom ID sets" refers to arrays indexed by content ids. The ID set contains data applying to all instances of content of a specific type. This is typically metadata or data controlling how code will interact with each type of content. Each vanilla ID class contains a SetFactory instance called "Factory" which is used to initialize the ID sets contained within the ID class. For example `Factory` is used to initialize `IsFood` with true values for food items such as `PadThai`. Modded content updates ID sets in `SetStaticDefaults`: `ItemID.Sets.IsFood[Type] = true;`. Code in tModLoader and individual mods might consult the data in `IsFood` for whatever purpose they want. Mods can make their own custom ID sets through the methods of this class. The `CreateNamedSet` methods create custom ID sets that facilitate collaborative "named ID sets". Mods using the same "named ID set" will share a reference to the same array merging together all the entries and changes. More information can be found in the Custom and Named ID Sets pull request.

| Member | Kind | tModLoader | What it does |
|---|---|---|---|
