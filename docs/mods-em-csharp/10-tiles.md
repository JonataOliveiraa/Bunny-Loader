# Tiles

`ModTile` registers new tile types in the mobile game's native tile registry. `GlobalTile` adds hooks to existing tile types. The API follows the local tModLoader checkout, including `ModTile.RandomUpdate(int i, int j, bool underground)`.

## Register a block

```csharp
using Microsoft.Xna.Framework;
using Microsoft.Xna.Framework.Graphics;
using Terraria;
using Terraria.ID;
using Terraria.ModLoader;

public sealed class ExampleBlock : ModTile
{
    public override void SetStaticDefaults()
    {
        Main.tileSolid[Type] = true;
        Main.tileMergeDirt[Type] = true;
        Main.tileBlockLight[Type] = true;
        DustType = DustID.Stone;
        MinPick = 50;
        MineResist = 2f;
        AddMapEntry(new Color(200, 200, 200));
    }
}

public sealed class ExampleBlockItem : ModItem
{
    public override void SetDefaults() => Item.DefaultToPlaceableTile(ModContent.TileType<ExampleBlock>());
}
```

The texture uses `Texture`, following the same namespace and file rules as `ModItem`. Put the block sheet beside the tile source and the inventory texture beside the item source. `Type` is a `ushort` allocated after the game's tile types. Always resolve it through `ModContent.TileType<T>()`; numeric IDs can change with the enabled mods.

`SetStaticDefaults` runs after the native arrays have grown. It can set `Main.tileSolid`, `tileFrameImportant`, `tileNoAttach`, `tileLavaDeath`, `tileLighted`, `TileID.Sets` and the other per-type tables. Solid tiles also receive `tileNoSunLight`; `tileLavaDeath` also sets `tileObsidianKill`.

`DustType`, `HitSound`, `MineResist` and `MinPick` control mining. `HitSound` accepts the game's `SoundID` values and `LegacySoundStyle` values through `SoundStyle`; null suppresses the mining sound. Custom audio asset loading is outside this tile implementation.

`AddMapEntry(Color, LocalizedText)` installs the map color and localized legend entry. Omitting the name uses `CreateMapEntryName()`. Map option selection currently uses the mobile default; `GetMapOption` is reserved for a later map extension. The mobile legend supports a name per map entry, rather than coordinate-dependent name callbacks; the callback overload reports `NotSupportedException`.

## Objects and crafting stations

```csharp
using Terraria.DataStructures;
using Terraria.Enums;
using Terraria.ObjectData;

public override void SetStaticDefaults()
{
    Main.tileFrameImportant[Type] = true;
    Main.tileNoAttach[Type] = true;
    TileObjectData.newTile.CopyFrom(TileObjectData.Style2x2);
    TileObjectData.newTile.Origin = new Point16(0, 1);
    TileObjectData.newTile.CoordinateHeights = new[] { 16, 18 };
    TileObjectData.newTile.AnchorBottom = new AnchorData(AnchorType.SolidTile, 2, 0);
    TileObjectData.newTile.StyleHorizontal = true;
    TileObjectData.addTile(Type);
    AdjTiles = new[] { (int)TileID.WorkBenches };
}
```

The native setup window temporarily releases `TileObjectData.readOnlyData` for tile defaults. It restores the lock after setup and retains the registered data when the game recreates its tables. Register the copied template with `addTile(Type)` during `SetStaticDefaults`.

`CoordinateHeights` copies between a C# `int[]` and the game's managed array. `Origin` and `AnchorBottom` use the game's `Point16` and `AnchorData` layouts. `Main.tile[x, y]` uses the mobile tile offset, including its interned tile storage.

The object check validates its cells and placement anchors. Breaking one cell removes the remaining object, produces its item drops once, then calls `KillMultiTile` with the object's top-left cell and style frame coordinates.

`AdjTiles` makes the tile count as other crafting stations. `GlobalTile.AdjTiles` is evaluated during setup. `Recipe.AddTile<T>()` accepts a `ModTile`; the mobile crafting station icon uses its placing item. Housing furniture flags in `TileID.Sets.RoomNeeds` also populate the corresponding type lists.

## World and interaction hooks

`KillTile` receives mutable failure, effects-only and no-item flags. `CanKillTile` can veto mining. `NumDust` limits the dust generated by that kill and `CreateDust` can change its type or cancel it. `KillSound` can suppress sound. `CanPlace`, `PlaceInWorld`, `CanExplode`, `CanReplace`, `Slope`, `TileFrame`, `HitWire`, `RandomUpdate` and `NearbyEffects` are available on both tile classes where tModLoader defines them. `GlobalTile.PreHitWire` can veto wiring before the game's handler.

`CanDrop` can suppress drops. A `ModTile` can use `RegisterItemDrop(itemType, styles)` or return items from `GetItemDrops`. Without an explicit drop, the loader finds the mod item whose `createTile` and `placeStyle` match. The actual drop path supports multiple returned items. The mobile `KillTile_GetItemDrops` query exposes the game's two item slots. Multi-cell objects suppress individual cell drops and drop through their whole-object path. `GlobalTile.Drop` runs after successful drop processing.

On mobile, a touch needs a cursor item icon before it reaches `RightClick`. The loader provides the placing item's icon when the hook is overridden. It debounces the game's three calls in one frame and repeated calls while the touch is held. `MouseOver` and `MouseOverFar` keep their own hooks. Containers, dressers, sitting and sleeping need additional systems and are deferred.

`ModifyLight` supplies tile light. The mobile renderer has an internal light helper that cannot be replaced by an ordinary managed hook. The loader scans only marked tile types in the lighting area and applies the cached light during the world update. Global light contributions use the same additive mobile path; they do not replace the game's internal emission calculation.

`IsTileDangerous` and `IsTileSpelunkable` run in the native tile renderer with the current cell coordinates. Global nullable results follow tModLoader: false vetoes highlighting, true enables it, and null preserves the previous result.

## Drawing

`AnimateTile` modifies `Main.tileFrame[Type]` and its counter. `AnimationFrameHeight` sets the vertical distance between animation frames. `AnimateIndividualTile`, `SetDrawPositions` and `SetSpriteEffects` adjust the native draw data only for types with the corresponding override.

`PreDraw`, `DrawEffects` and `PostDraw` run on the rendering thread. A tile using `PreDraw` or `DrawEffects` suppresses its normal base draw and receives a base draw in that pass when `PreDraw` permits it. A reused `TileDrawInfo` supplies the cell's frame, dimensions, offsets, texture, color and effects. `Main.instance.TilesRenderer.AddSpecialLegacyPoint(i, j)` queues `SpecialDraw` for the same pass. Global drawing hooks also apply to vanilla tiles.

Global hook arrays are prepared once at content setup. Crafting station aliases are merged per tile type, and adjacency updates visit only types with extra aliases. Tile and NPC statue handlers share a wiring scope, so global pre/post wiring hooks run once around king/queen statue handling regardless of installation order.

The native filter avoids entering C# for unmarked types during framing, random updates and native draw-data processing. Area scans return only matching cells into reused buffers. Reflection runs during registration, rather than once per cell. Drawing uses the mobile overlay path; specialized vanilla slope, paint, glow and liquid rendering remain in the game's renderer.

## Chests and dressers

A chest is a 2x2 `ModTile` with `TileID.Sets.BasicChest` (a dresser: 3x2 with
`TileID.Sets.BasicDresser`) and the game's own chest placement hooks, as in
tModLoader:

```csharp
TileObjectData.newTile.HookCheckIfCanPlace = new PlacementHook(Chest.FindEmptyChest, -1, 0, true);
TileObjectData.newTile.HookPostPlaceMyPlayer = new PlacementHook(Chest.AfterPlacement_Hook, -1, 0, false);
```

On the phone `PlacementHook` takes these two game methods (other methods are
refused). The items live in the game's `Main.chest`, saved with the world as
the game's chests. `RightClick` opens it (`player.OpenChest`) and
`KillMultiTile` calls `Chest.DestroyChest`; see `ExampleChest` and
`ExampleDresser` in the ExampleMod.

- `IsLockedChest(i, j)`, `UnlockChest(i, j, ref frameXAdjustment, ref dustType, ref manual)`
  and `LockChest(i, j, ref frameXAdjustment, ref manual)` answer `Chest.IsLocked`,
  `Chest.Unlock` and `Chest.Lock`; without `manual`, the 2x2 frame moves by
  `frameXAdjustment` (36 to lock, -36 to unlock) with the unlock sound and dust.
- `DefaultContainerName(frameX, frameY)` is the name `TileLoader.DefaultContainerName`
  gives (for the cursor text, as the ExampleMod does).
- The chest and dresser pages of the inventory show the item the tile drops.
- A mod dresser stays open while the player is next to it and opens the
  clothes window, which the phone otherwise keeps for the game's dresser only.
- In multiplayer, placing and breaking a mod chest or dresser goes to the
  server through the loader's own packet (the game's message only knows its
  three container tiles), as tModLoader's extra actions of that message do.

`AddMapEntry` with a name callback (`MapChestName` in tModLoader) is not
available: the phone's map legend only takes fixed names.

## Tile entities

A `ModTileEntity` keeps data and code on one placed object, as in tModLoader:

```csharp
public class BasicTileEntity : ModTileEntity
{
    public override bool IsTileValidForEntity(int x, int y)
    {
        Tile tile = Main.tile[x, y];
        return tile.HasTile && tile.TileType == ModContent.TileType<BasicTileEntityTile>();
    }
}
```

The tile places it and removes it:

```csharp
TileObjectData.newTile.HookPostPlaceMyPlayer = ModContent.GetInstance<BasicTileEntity>().Generic_HookPostPlaceMyPlayer;

public override void KillMultiTile(int i, int j, int frameX, int frameY) => ModContent.GetInstance<BasicTileEntity>().Kill(i, j);
```

`TileEntity.TryGet(i, j, out BasicTileEntity entity)` finds the entity of the
object that has the cell (i, j). Each entity has `ID`, `Position` (the top
left cell, a `Point16`) and `Type`; the template (`ModContent.GetInstance`)
has `Place`, `Kill`, `Find` and `ModTileEntity.CountInWorld()`.

- `Update` (only when overridden, `RequiresUpdates`), `PreGlobalUpdate` and
  `PostGlobalUpdate` run on the server (or alone) once per world update,
  around the game's own tile entities.
- `SaveData`/`LoadData` keep the data in `<world>.wld.bl.json`; when the world
  loads, an entity whose tile is no longer valid (`IsTileValidForEntity`) is
  dropped, and entities of mods that are not loaded are kept as they were.
- `NetSend`/`NetReceive` carry it to clients: when it is placed, when a player
  gets that part of the world, and on `NetMessage.SendData(MessageID.TileEntitySharing, number: ID)`.
  A client's placement asks the server, which checks the tile, places it,
  calls `OnNetPlace` and sends it to everyone. `OnKill` runs on `Kill`.
- `Hook_AfterPlacement` and other C# methods also work in a `PlacementHook`
  for `HookPostPlaceMyPlayer`.

The game itself cannot hold new tile entity classes, so mod entities live in
the loader and are not in the game's `TileEntity.ByID`; use `TileEntity.TryGet`.

## Walls

A `ModWall` is written as in tModLoader; the texture is found the same way as a tile's:

```csharp
public class ExampleWall : ModWall
{
    public override void SetStaticDefaults()
    {
        Main.wallHouse[Type] = true;
        DustType = ModContent.DustType<Sparkle>();
        AddMapEntry(new Color(150, 150, 150));
    }

    public override void NumDust(int i, int j, bool fail, ref int num) => num = fail ? 1 : 3;
}

public class ExampleWallItem : ModItem
{
    public override void SetDefaults() => Item.DefaultToPlaceableWall(ModContent.WallType<ExampleWall>());
}
```

- The wall drops the mod item that places it; `RegisterItemDrop(itemType)` sets another one, and `Drop(i, j, ref type)` can change or cancel it.
- `KillWall`, `NumDust`, `CreateDust` (starting from `DustType`), `KillSound` (then `HitSound`) run when the wall is hit or broken.
- `WallFrame(i, j, randomizeFrame, ref style, ref frameNumber)`, `RandomUpdate`, `AnimateWall(ref frame, ref frameCounter)` and `ModifyLight` run only for walls that override them; the cell filter is native, so other walls cost nothing.
- `Tile.WallType`, `WallFrameX`, `WallFrameY` and `WallFrameNumber` read and write a cell's wall; `WallLoader.GetWall(type)` and `WallLoader.WallCount` work as in tModLoader.
- Mod walls are saved in `<world>.wld.walls.bl` by mod and name (the `.wld` keeps no mod wall), so their numeric IDs may change between sessions. A wall of a mod that is not loaded is kept in the file, with the loader's unloaded wall in its place.

Not available yet: `GlobalWall`, `CanPlace`, `PlaceInWorld`, `CanExplode`, `PreDraw`/`PostDraw` (the mobile game draws walls in one threaded pass), `CanBeTeleportedTo`, biome conversion (`WallLoader.RegisterConversion`, `OnWallConverted`) and the coordinate-dependent map name.

## Trees

A `ModTree` is written as in tModLoader and is loaded on its own (it is not a `ModType`). The tree grows from the vanilla tree tile (5) on the ground tiles in `GrowsOnTileId`:

```csharp
public class ExampleTree : ModTree
{
    private Asset<Texture2D> texture, branchesTexture, topsTexture;

    public override TreePaintingSettings TreeShaderSettings => new TreePaintingSettings { UseSpecialGroups = true };

    public override void SetStaticDefaults()
    {
        GrowsOnTileId = [ModContent.TileType<ExampleBlock>()];
        texture = ModContent.Request<Texture2D>("ExampleMod/Content/Tiles/Plants/ExampleTree");
        branchesTexture = ModContent.Request<Texture2D>("ExampleMod/Content/Tiles/Plants/ExampleTree_Branches");
        topsTexture = ModContent.Request<Texture2D>("ExampleMod/Content/Tiles/Plants/ExampleTree_Tops");
    }

    public override Asset<Texture2D> GetTexture() => texture;
    public override Asset<Texture2D> GetTopTextures() => topsTexture;
    public override Asset<Texture2D> GetBranchTextures() => branchesTexture;

    public override int SaplingGrowthType(ref int style)
    {
        style = 0;
        return ModContent.TileType<Plants.ExampleSapling>();
    }

    public override int DropWood() => ModContent.ItemType<ExampleItem>();
}
```

- The trunk, branch and top textures use the vanilla tree sheet layouts (the trunk is a 176-pixel-wide strip, the tops are three 80x80 frames).
- An acorn planted on the ground becomes the sapling returned by `SaplingGrowthType`. The sapling is a `ModTile` with `TileID.Sets.TreeSapling[Type] = true`; its `GrowSapling` is called by `WorldGen.AttemptToGrowTreeFromSapling`, and `WorldGen.GrowTree` accepts it.
- `CountsAsTreeType` (`TreeTypes.Custom` by default), `TreeLeaf`, `Shake`, `CreateDust`, `CanDropAcorn` and `DropWood` work as in tModLoader; `PlantLoader.Get<ModTree>(TileID.Trees, groundType)` finds the tree.
- Not available yet: `ModPalmTree`, `ModCactus`, `SetTreeFoliageSettings` (it is not called) and tree painting (`TreeShaderSettings` is not used). `TileID.Sets.TreeSapling` is kept by the loader, since the mobile game has no such set.

## Pylons

A `ModPylon` is a `ModTile` with a `TEModdedPylon` entity, written as in tModLoader:

```csharp
public sealed class SimplePylonTileEntity : TEModdedPylon { }

public class ExamplePylonTile : ModPylon
{
    public override void SetStaticDefaults()
    {
        Main.tileFrameImportant[Type] = true;
        TileObjectData.newTile.CopyFrom(TileObjectData.Style3x4);
        TEModdedPylon moddedPylon = ModContent.GetInstance<SimplePylonTileEntity>();
        TileObjectData.newTile.HookCheckIfCanPlace = new PlacementHook(moddedPylon.PlacementPreviewHook_CheckIfCanPlace, 1, 0, true);
        TileObjectData.newTile.HookPostPlaceMyPlayer = new PlacementHook(moddedPylon.Hook_AfterPlacement, -1, 0, false);
        TileObjectData.addTile(Type);
        AddToArray(ref TileID.Sets.CountsAsPylon);
        AddMapEntry(Color.White, CreateMapEntryName());
    }

    public override void KillMultiTile(int i, int j, int frameX, int frameY) => ModContent.GetInstance<SimplePylonTileEntity>().Kill(i, j);
}
```

- Each `ModPylon` gets a `PylonType` after the game's (11, 12, ...). Its entities join the game's pylon list (`Main.PylonSystem`), so `HasPylonOfType`, teleporting, the "near a pylon" check and multiplayer sync work with the game's own code.
- `CanPlacePylon` (one per type by default), `ValidTeleportCheck_NPCCount` and `ValidTeleportCheck_BiomeRequirements` (called with the `SceneMetrics` scanned around the destination) decide placement and teleporting.
- `DrawMapIcon` draws the icon on the full map, usually with `DefaultDrawMapIcon` and `DefaultMapClickHandle`. `SpecialDraw` with `DefaultDrawPylonCrystal` draws the floating crystal (`DrawEffects` already asks for `SpecialDraw` once per pylon).
- Touching the pylon opens the map in the mobile pylon mode, framing every revealed pylon, like a vanilla pylon.
- `GetNPCShopEntry` adds the pylon item to town NPC shops, except those in `NPCShopDatabase.NoPylons`.
- Not available yet: `GlobalPylon`, `ValidTeleportCheck_DestinationPostCheck`, `ValidTeleportCheck_NearbyPostCheck`, `ModifyTeleportationPosition`, the smart cursor crystal highlight, `HasSmartInteract`, and the `TileFrame` override tModLoader uses to break a pylon. `TileID.Sets.CountsAsPylon` is kept by the loader, since the mobile game has no such set.

## World persistence

C# uses the existing native `.wld.tiles.bl` backend. Its stable tile key is `<mod UID>/<tile name>`, shared with JS. A JS mod and its C# port must keep both values to reuse saved tiles. No conversion of the sidecar format is needed.

The native backend saves tile coordinates, type keys, frames and tile headers, restores the tile object's registered shape, and preserves unresolved entries when their cells remain empty. The ordinary `.wld` contains the compatible vanilla world. Keep the `.wld.tiles.bl` file with the world. This backend currently leaves missing tiles empty in the vanilla file; `VanillaFallbackOnModDeletion` does not change that mobile save behavior.

## Examples and validation

`ExampleModCSharp` includes the original ExampleMod block and workbench textures, `ExampleBlockItem`, the workbench item, a crafting station alias and a recipe requiring the custom workbench.

```sh
DEVICE=127.0.0.1:16416 bash tools/tests/run-cs.sh cstile
DEVICE=127.0.0.1:16416 KEEPSAVES=1 bash tools/tests/run-cs.sh cstile
```

To check a JS world, run `QJS=true DEVICE=127.0.0.1:16416 bash tools/tests/run-cs.sh cstilelegacy`, then run `cstile` with `KEEPSAVES=1`. The legacy writer deliberately registers an additional tile first, so the Block numeric ID differs while its UID/name key remains the same.

The second run preserves the saved test world and verifies the tile at its fixed persistence coordinate. The suite exercises registration, object data, map legend, simple and 2x2 placement/breaking, drops, mining hooks, direct touch interaction, animation, light, drawing and global hooks on vanilla tiles.

The `cschest`, `cstileentity` and `cswall` packs (each run twice, the second time with `KEEPSAVES=1`) check chests, dressers, tile entities and walls; `cstree` checks trees and `cspylon` pylons. `TileRestingInfo` is deferred to the next phase-5 step.
