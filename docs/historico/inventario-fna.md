# FNA inventory

Generated by `tools/docs/FnaInventory` (do not edit by hand; decisions go in
`tools/docs/FnaInventory/decisions.txt`). It compares the public API of FNA as
tModLoader ships it (`exmod_tmod/tModLoader/FNA`, submodule) with the mobile
game's own XNA (`refs/dump.cs`) and with what `BunnyLoader.dll` exposes to mods
(hand-written sources plus the ProxyGen output). Missing members per type are in
`tools/docs/FnaInventory/members.txt`.

Kinds:

- `done`: every public member of the FNA type exists in BL with the same signature.
- `1 copy`: plain managed code in FNA (no FNA3D, FAudio, SDL or platform call);
  it can be copied (Ms-PL, keep the notice) and converted where it crosses the bridge.
- `2 game`: built over what the mobile game or Unity already has, as
  `Texture2D.SetData` was (the tool guesses it when the game has the type).
- `3 native`: FNA calls native code and the game lacks the type: new native code
  (GL on the render thread, like the sprite shaders).
- `out`: belongs to the engine the game already owns (window, game loop, device
  setup, SDL input, FAudio), decided in `decisions.txt`.
- A kind with `?` is the tool's guess; one without it was decided by hand.

Columns: **BL** members with the same signature / FNA members (`+n` more exist
with another signature); **Game** whether the mobile dump has the type;
**ExampleMod** how many times tModLoader's ExampleMod names the type.
