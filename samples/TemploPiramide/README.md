# Templo Pirâmide (Pyramid Temple)

A JavaScript mod for Bunny Loader, Terraria Mobile 1.4.5.6 (build 301720).

`content/temple-plan.js` generates the layout without touching the game. `content/temple-runtime.js` places the tiles and updates `GenVars` for Terraria's `templePart2` step. `content/main.js` registers the hook when the mod loads.

Installation and behavior: [description.md](description.md).

To test the geometry and the integration with a simulated bridge:

```powershell
node tools/temple/check.mjs
```

To update the standalone Editor script and build the importable ZIP:

```powershell
python tools/temple/package.py
```

Outputs: `tools/editor/templo.js` and `out/TemploPiramide.zip`. The Editor script installs a single hook per process; running it again updates the generator. Run it before creating a world, without closing the game. The script keeps the previous version's global names `buildTemple` and `templeHooked` to allow updating within the same session.

To render the tested layout and update the icon (Python with Pillow):

```powershell
node tools/temple/check.mjs
python tools/temple/preview.py
python tools/temple/package.py
```

The preview generated by the tests shows the layout with the planned chest, sign and emitter locations, before the game's extra decoration. The local tests do not replace validating world creation and the Golem fight on Android.

The generator never calls `makeTemple`'s original callback, not even after failures. The exception is contained because the Bunny Loader bridge runs the original automatically when the callback throws.

References checked in the local source provided by the user (`TerrariaSource/Terraria`): `WorldGen.makeTemple`, `WorldGen.PlaceDoor`, `WorldGen.AddLihzahrdAltar`, `WorldGen.templePart2`, `WorldGen.mayanTrap`, `WorldGen.AddBuriedChest`, `WorldGen.AddWireFromPointToPoint`, `Chest.NearOtherChests` and `Wiring`. The signatures the mod calls were also checked against the Mobile version's dump. Terraria's source code is not included in the package.
